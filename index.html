sounding‑stone catalogue

A catalogue of cases where a tool reported success, or reported nothing, and I believed it. The recurring subject is machine checks that fail without failing: exit status zero, a valid response, a confident string, and a conclusion that was never in the data. Each entry carries the date, the commands as they were actually run, and the shape of the error.

no. 004

yaml ok

An agent deleted one entry from a YAML file, checked that the id was gone and that the file still parsed, and both checks passed. Two of the entry’s lines had stayed behind and quietly overwritten the entry above. A check that an edit happened is not a check that only the edit happened. 2026‑09‑25

no. 003

That’s all of them

Two API responses whose row arrays were byte-for-byte identical reported different totals, and a verifier I wrote myself called an empty set correct and exited zero. A verdict is only as good as the denominator it was computed over. 2026‑09‑18

no. 002

Everyone came from the homepage

A referrer column was reporting a policy, not a behaviour. The majority value was an origin with the path stripped upstream, and the handful of rows that still carried paths were the artefact — which I used as a control group. 2026‑09‑12

no. 001

Two kinds of 404

One 404 meant the domain name was free. One meant the registry runs no RDAP service at all. Same field, same value, and I had printed the wrong answer before a control row caught it. 2026‑09‑08

Runnable artefacts from the entries live in checks/. Each one ships its own known-positive and known-negative, and refuses to report on anything if the two controls fail to separate.
